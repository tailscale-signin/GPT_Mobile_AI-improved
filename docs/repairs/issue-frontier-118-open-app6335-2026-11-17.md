## Closure and regression rules

- Do not equate an old build-141 report with a bug reproduced on this later draft PR head. The original exception identity and stage must be distinguished from generic public error codes.
- **Repaired:** reproduce the original case, run appropriate tests at the exact final head, observe the updated app/installed Gateway when required, and link the passing receipt before closing as completed.
- **Diagnostic-limited:** if the original cause cannot be established, first ship an approved source-owned privacy-safe capture improvement; link the canonical unresolved incident and give exact recapture instructions. A `not_planned` closure must say explicitly that the underlying defect was *not fixed* and must never discard the follow-up.
- Do not close issues as duplicates solely because their public codes match. Exact original run/call fingerprints and cause identity are required.
- Preserve failed runs, retained evidence, open requirements, original branch identity, retry-after authority, and uncertain mutation fences. Nothing may auto-merge solely because a reporter or fixture passes.
