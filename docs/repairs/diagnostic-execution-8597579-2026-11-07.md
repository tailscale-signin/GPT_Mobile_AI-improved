## Implemented changes

### Consume the exact saved-page correction once

Three distinct calls at capture lines 101–103 were rejected before dispatch. Each attempted `github_context` with a saved `view_cursor` and context selectors that did not match its retained request. The native result already supplied a cursor-only `correction_call`. Rejecting the changed context was correct.

The remaining defect was in deterministic checklist recovery. It recognized only the three `SAVED_VIEW_*` error codes, while this precheck used `INVALID_ARGUMENTS`. Recovery was also behind an equality comparison between an issued cursor-only request and the failed request; extra selectors necessarily defeated that comparison. A valid native correction could therefore remain unused.

[GitHubResultViews.kt](../../app/src/main/kotlin/dev/chungjungsoo/gptmobile/data/agent/tool/GitHubResultViews.kt) now identifies this rejection with `reason=SAVED_VIEW_CONTEXT_MISMATCH` and the names of conflicting fields. It keeps the existing error code and cursor/context validation. No selector value is added to diagnostics.

[GitHubTestChecklist.kt](../../app/src/main/kotlin/dev/chungjungsoo/gptmobile/data/github/GitHubTestChecklist.kt) now considers the correction from the trusted failed receipt directly. Compatibility with retained old receipts requires all of the following: a non-dispatched `INVALID_ARGUMENTS` result, the native `github.arguments.v1` schema and matching operation, the same selected model-visible tool, and an exact correction containing only the same string cursor. The current tool schema, allowed read action, tool budget, and verification eligibility still apply. Branch selection, graph index/note, changed cursors, another connection's tool, extra repository selectors, and mutations cannot use this path.

The existing receipt history spends at most one correction per saved view or exact recovery recipe, including after restoration and at another offset. An unsuccessful correction does not receive a new retry allowance. The planner can still perform a separate currently authorized read. Successful correction consumption closes the corresponding pending failure for inventory coverage. No new recovery store or coordinator was introduced.

The five behavioral cases in [GitHubSavedPageRepairTest.kt](../../app/src/test/kotlin/dev/chungjungsoo/gptmobile/data/github/GitHubSavedPageRepairTest.kt) exercise the actual `GitHubResultViews` rejection, checkpoint persistence and restoration, exact local read consumption, foreign-scope rejection, legacy receipts, one-repair limits, inventory completion, forged recovery recipes, permission exclusions, selected-tool removal, and exhausted budgets.
