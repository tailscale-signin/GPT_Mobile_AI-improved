## Reproduced diagnostic repair

`CombinedRecordRecoverySession` already stopped an accepted append when the saved checkpoint could not establish the previous request's completion. That condition, original event code, early return and no-replay behavior remain intact. The event now carries the application-owned final-synthesis stage, reconciliation requirement, non-retryable/non-resumable status and `REVIEW_SAVED_RECOVERY` action. Its causal identity identifies the saved cursor check, not a provider invocation, and the approved diagnostic projection hashes it.

`IssueReportIncidents.chatFailure` maps the complete matching application-owned tuple to the existing public `REMOTE_OUTCOME_UNKNOWN` code. The original code hash is preserved. An incomplete tuple, provider-owned origin, retryable state or missing reconciliation evidence cannot acquire that classification. The change does not infer dispatch, provider acceptance, HTTP status, invocation identity or a remote job from the application guard.

The full `CombinedAppendRecoverySessionTest` and `IssueReportIncidentsTest` classes join the early Android regression gate. That gate now selects 14 complete classes. Its result artifacts remain separate from the full-suite artifacts, and the full suite still reruns all tests.
