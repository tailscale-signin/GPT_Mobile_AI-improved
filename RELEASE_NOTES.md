## Qualification and remaining limits

Publication requires successful validation of the final PR head, main revision and signed artifacts. The release workflow records source identity, checksums, signing/provenance evidence and publication receipts.

- Unified Reliability v2 is not complete; this scoped release does not certify the broader milestone or unexecuted scenarios.
- Physical Android frame timing, export latency, model behavior and Windows-to-phone networking still require measurements on the target device and services. Automated regressions establish their tested behavior only.
- Provider balances, account/project/key limits, external rate limits and unavailable servers remain external conditions. Recovery controls do not replenish quota or override a provider rejection.
- Explicit local reasoning On/Off remains blocked unless the exact selected model and runtime provide a recognized, fresh template-control proof. Auto must be selected explicitly when that proof is unavailable.
- Bounded graph qualification demonstrates the selected first-party sample; it does not claim that every file or repository integration was exercised.
- French pronunciation, sustained background audio, GPU/NPU performance and end-to-end speech latency still require physical handset qualification. Host regressions exercise language selection, streaming and service ownership, acknowledgment handoff, parallel audio preparation, CPU thread scheduling and accelerator fallback.
- Unified Reliability v2 is not complete. This release qualifies the scoped GitHub mode and repository-context changes; broader program acceptance remains independent.
- Live provider answer quality, remote token savings and physical-phone latency require matched measurements. Deterministic and hosted regressions do not establish a measured intelligence score or superiority over another coding product.
- Repository caller, import, test and configuration relationships are bounded lexical candidates. Prepared source excerpts may be trimmed by final request admission and do not establish exhaustive repository coverage, compiler resolution or executed tests.
- OpenRouter capabilities are bound to the observed exact model ID and freshness window. Unsupported or custom-route capabilities remain unknown; explicit fixed reasoning settings retain their selected behavior.
- Qualification prerequisites, uncertain writes and missing source or execution evidence remain explicit. Recovery does not expand permissions, replay uncertain mutations or convert unfinished acceptance criteria into success.
- The repository and gateway regressions include simulated transports. Physical handset execution and live side-by-side model quality have not been measured for these changes. Provider quota and explicit reasoning-off support depend on the selected backend.

- The native campaign controller has no measured product-quality results. Synthetic fixtures and portable presentation checks do not establish Windows installation, native product execution or comparative superiority.
- Full voice benchmark measurements depend on the installed models, Android speech services, physical output route and device thermal state. Synthetic speech recognition and waveform measurements cannot rate human-perceived pronunciation.

Published tags remain immutable, and a passing earlier revision does not qualify a later commit.

- Source retrieval measurements and host fixtures do not establish handset performance, an upstream Copilot entitlement, or an installed-product quality score.
