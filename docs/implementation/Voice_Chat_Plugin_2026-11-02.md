# Opt-in Voice Chat plugin

Repository: `tailscale-signin/GPT_Mobile_AI-improved`. Branch: `feat/gateway-network-listener-no-tailscale-2026-11-01`, PR #780. Base: `main` at `83afa7f113b29ad050c21d5bde5ea55da6dae602`. This extends the user's gateway/desktop request with an optional Android voice experience. Desktop work through `dcce1d6d1c4a7c2ac3986c76dd7c0c2a925b4b7c` passed actual Windows installer and Python 3.12/3.13 Linux/Windows stability workflows. A subsequent layout adjustment fits smaller desktop screens.

Voice Chat has stable plugin ID `voice_chat` and defaults to disabled for new and existing settings. Its wave button sits immediately left of New Chat. The first press opens an opt-in screen with an AI profile selector and a short explanation of microphone/transcript handling. After enabling, pressing the button opens the full-screen voice session and requests microphone permission if needed. The opening panel expands from the button using the app's existing reveal motion. The main view uses the app theme, a central animated wave, live captions, mute, speaker, end and text-chat handoff controls.

The current implementation is a turn-based Android speech adapter, not the ChatGPT voice service. It prefers Android's on-device recognizer when available; otherwise the selected system recognition service may use its network. Final transcripts enter the existing durable ChatViewModel dispatcher and retain normal model selection, accounting and tool approval requirements. Only a completed assistant turn is read aloud. Tool/input approvals prompt a text-chat handoff. Recognition/model failures do not silently resend a request. Long replies read up to 12,000 characters with an announced handoff to the full written response.

No audio engine is started by installing or enabling the plugin alone. Recording starts only in the visible, enabled, permitted session. Audio stops on mute, pause, background, navigation and disposal. Returning from background requires a tap before capture/playback resumes. Capture is stopped during playback; tapping the wave interrupts speech and starts a new listening turn. Callback generation checks discard stale recognition and playback callbacks. Raw audio is not written to app storage. Recognized text and responses remain in the normal chat history.

`data/voice/VoiceAudio` and `VoiceSession.API_VERSION = 1` separate audio capture/playback from lifecycle and conversation orchestration. `AndroidVoiceAudio` is the bundled implementation. These boundaries prepare extraction into a separately distributed module; this change does not introduce a downloadable executable loader or claim that a separate plugin package is published. Plugin state uses the existing service catalog and preference serialization.

Validation: eleven platform-independent Kotlin/JUnit session tests run locally, covering opt-in/permission/foreground gates, one submission per utterance, late callbacks, no capture during playback, mute, interruption, speaker-off captions, explicit foreground resume, failures without replay, disposal and Unicode-safe speech chunks. Additional preference serialization/default-off tests are included for Android CI. Changed Kotlin files are checked with the repository's ktlint version. Full Android compilation, device permission/recognizer/TTS behavior and physical microphone acceptance require Android CI/device execution; local JDK 21/SDK 37 are unavailable.

Primary platform contracts: [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer) and [TextToSpeech](https://developer.android.com/reference/android/speech/tts/TextToSpeech). Speech APIs run on the main thread, recognition objects are destroyed, TTS is shut down, and manifest service queries are retained.
