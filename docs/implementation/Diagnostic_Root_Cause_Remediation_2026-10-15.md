# Build 121 diagnostic root-cause remediation

Branch: `fix/feature-audit-completion-2026-10-15`. Draft PR: https://github.com/tailscale-signin/GPT_Mobile_AI-improved/pull/690.

The supplied October 15 audit describes build 121 at `6b19a9338c42`. The figures and incident timings in that audit are user-supplied findings, not a new independent replay of the private export. This implementation preserves native quarantine, consent, exactly-once action guards and bounded acquisition. It does not certify physical ASUS execution, external server availability, scientific entailment or UI performance.

## Implemented root-cause changes

| Audit area | Concrete change and integration | Evidence boundary |
| --- | --- | --- |
| 3.1 Native quarantine | Parent-side durable native-route rejection is indexed after an explicit worker quarantine denial. Identity includes artifact bytes, runtime libraries/version, firmware/device and backend. Subsequent requests reject before metadata inspection, memory/context preparation, benchmark admission or the native queue. CPU rejection does not block the GPU route. Native-route reads use a separate journal lock, so a blocked request does not wait behind another route’s in-flight load. Ordinary retry never clears the worker journal. Explicit Verify load resets the matching parent index only after worker reset acknowledgement. | A pre-existing worker-only marker must first be surfaced by the worker; this branch does not guess a route from an opaque old digest. Existing isolated Verify load and Android exit journal remain authoritative. |
| 3.1 Watchdogs | Every `LiteRtLmAdapter` session now uses the existing progress watchdog, including ordinary chat, research/delegation and benchmark entry points. User profile deadlines are forwarded for primary and delegated writers. Productive text, reasoning and monotonic native counters count as progress; notices do not. Cancellation retains the runtime lease until cleanup acknowledges termination. | Healthy hardware generation, stuck JNI teardown and tombstone acquisition still require the actual device. |
| 3.2 Research | Circuits are keyed by stage plus endpoint/model identity, rather than profile alone. Two failed PLAN calls no longer suppress EXTRACT/REVIEW. A failed stage admits one half-open recovery probe after a 30-second cooldown; pinned authorized fallback remains available. Failure events distinguish READINESS versus GENERATION and retain sanitized category/exception type without source text. | Existing source journals, extraction ledgers and partial-coverage disclosures are retained. These changes cannot create reviewed claims when every authorized model/provider is unavailable. |
| 3.3 Search | Existing normalized-query reuse, selected-provider concurrency, sibling evidence retention and per-engine cooldowns are retained. DNS, timeout and authentication failures receive separate outcomes. Duplicate actions are separated from permission denial; a denied source is no longer presented as a successful empty search. | Only selected, authorized sibling providers are eligible. No hidden alternate credentials or search engine is enabled. |
| 3.4 MCP | Existing protocol negotiation, single-flight session/catalog reuse, endpoint health/backoff and authentication-required exclusion are retained. Added a legacy Streamable HTTP integration fixture where standalone GET returns 405 while initialization, tool listing and execution succeed through POST. | Port 8101 connection refusal, host/firewall exposure, DNS and expired provider credentials require service/account repair outside this repository. GET 405 alone must not be classified as a broken MCP session. |
| 3.5 Provider recovery | Shared credential-scoped cooldown now paces requests during a bounded 30-second recovery period instead of releasing a synchronized retry burst. OpenAI-compatible overload responses also register cooldown; Gemini and Anthropic use the same registry. Anthropic transient/overload retries are bounded and occur only before any response payload. Retry-After applies to overload as well as rate limits. Wait notices propagate through the existing response channel. | Normal unthrottled requests stay concurrent. Different credentials do not share throttles. No model/account switching is introduced. |
| 3.6 Tool admission | Existing schema/argument/batch/owner/result budgets remain. `authorizeOrThrow` distinguishes `DUPLICATE_ACTION` from `AUTH_REQUIRED`, and the budget wrapper returns the exact typed, non-dispatched rejection. Reusing a prepared closure returns `DUPLICATE_INVOCATION`, not budget exhaustion. Unmarked inherited cancellation is labeled PARENT_CANCELLED, not guessed as user intent. | Oversized unsafe batches remain rejected before dispatch; mutation batches are not silently split. Existing recovery grants/fresh-request UI remains on the same branch. |
| 3.7 Rendering | The initial branch moves checkpoint work into existing background preparation and restores navigation without starting background inference. Existing incremental rendering throttles and frame telemetry remain. | No measured claim of eliminating the recorded EGL/3.7-second stalls. Release-equivalent Perfetto, IME and GPU-contention profiling is still required. |
| 3.8 Output | Continuations stop after two output-limited requests each reporting at least 1,024 output tokens but producing at most 256 novel visible UTF-8 bytes. One tool-free continuation is allowed; a third wasteful request is prevented. Saved prefixes/evidence survive. Usage reduction preserves finish, retry, runtime and reported reasoning metadata. OpenAI Responses `max_output_tokens` is explicitly recognized. | Visible byte counts are not asserted to be tokenizer counts. Reported reasoning tokens propagate for supported Chat Completions, Responses and Gemini payloads; unreported tool/visible token breakdowns stay unknown. |
| 3.9 Memory | Every eligible enrichment source is durably marked before asynchronous WorkManager admission. Admission failure retains the marker and records an explicit enqueue failure. Already completed sources clear stale markers. Existing idle/runtime-change resumption, retry limits and diagnostic backlog count remain. | Worker/device scheduling and battery constraints still determine when work can run. Exact native tokenizer integration is unchanged; estimates remain explicitly unmeasured. |
| 3.10 Local Assist | Native-stage watchdog and failure isolation apply to local helper sessions, while existing Assist lifecycle, inclusion receipts and independent optional-failure paths remain. | No unsupported native function calling is advertised. This branch does not certify actual contribution without invocation and inclusion evidence. |
| 3.11 Large methods | New recovery/throttle/checkpoint logic is kept in small focused components. | The large existing preparation/runner/provider coroutine methods still need a measured, separate structural refactor; no assumption is made that refactoring fixes EGL stalls. |
| 3.12–3.13 Platform/startup | Existing signal-exit classification, optional discovery deadlines and Smart Readiness isolation are retained. New native preflight skips known blocked work early; normal remote chat does not acquire a local-model dependency. | Platform/IME/vendor warnings are not suppressed. Device exit reasons and background service lifecycle require actual measurements. |

## Regression coverage

Added or extended tests cover stage circuit isolation and cooldown, sanitized pre-invocation failure diagnostics, durable/scoped native-route blocking, adapter rejection before inspection, native progress timeout, shared provider recovery pacing, duplicate-versus-permission admission, POST-only MCP behavior, Responses incomplete/reasoning metadata and repeated low-yield continuations. The initial branch also covers memory preparation rebuild, completed-pass restart, permission revocation during repair, encrypted checkpoint persistence and fresh-conversation scope isolation.

An isolated Kotlin 2.1.20/JVM harness passed 40 tests using production recovery, circuit, numerical, throttle and readiness components. Android/runtime/accounting contracts unavailable locally were replaced by minimal test stubs; this is not a full app build. The real project uses its committed Kotlin/Android versions in CI. Ktlint 1.3.1 is run locally across all changed Kotlin files. The 116 repository Python tests and resource/schema/regex checks are separate from device acceptance.

CI on the initial published revision found formatting violations. Those were corrected locally with the exact ktlint version; final CI must validate the updated branch. No task or device acceptance case is marked complete merely because these fixtures pass. Main/release status is unchanged until an independently authorized, qualified merge/release.
