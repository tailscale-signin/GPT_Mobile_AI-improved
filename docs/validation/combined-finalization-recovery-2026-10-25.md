# Combined synthesis and recovery validation

## Scope and evidence

This change set addresses the two supplied audits: the focused Combined answer export and the wider 6,886-record diagnostic export recorded at commit `019f5828` (version `0.9.60.0`, build 128, debug). The diagnostic counts describe that exported build. They are not measurements of this branch.

The focused export showed a generated overview followed by substantial locally copied source material, source IDs attached to broad or unrelated passages, lost partial attribution after an exact copy appeared elsewhere, and a mixed animal/human qualification that did not match itself. The wider audit showed a detached-layout crash during finalization, a text-before-metadata persistence window, stale quality checks after local assembly, provider-specific recovery failures, diagnostic evidence loss and rendering stalls.

The implementation keeps one primary synthesis generation for an accepted strict single-pass turn. Full original contributions remain immutable and inspectable. The writer receives readable claims and a topic plan and must integrate distinct relevant details, disagreements and qualifications into the answer. Deterministic text linking remains conservative: an unresolved link is not proof of omission, and a contributor colour is not factual verification.

## Reproducible verification

### Repository and packaged checks

Use the repository's Java/SDK versions and normal CI environment:

```sh
./gradlew :app:testDebugUnitTest :app:jacocoTestReport
./gradlew :app:lintDebug
./gradlew :app:assembleDebug
python3 scripts/check_research_dispatch_size.py <path-to-produced-review-apk>
```

The last command must inspect the APK that was actually built from the reviewed commit. Retain the test XML, lint report, size-check output and commit SHA with the PR. If a failure is caused by an implementation change, repair it and rerun the affected acceptance cases before rerunning the final required gates.

### Compose finalization lifecycle

Run the connected test on an API level supported by the project:

```sh
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=dev.chungjungsoo.gptmobile.presentation.ui.chat.CombinedFinalizationLifecycleInstrumentedTest
```

The test repeatedly changes from the live inline answer to the final document while a pointer is down, scrolls, changes revision identity and removes/recreates the renderer. The Robolectric `CombinedFinalizationLifecycleTest` additionally exercises a held text selection and profile identity changes. A pass covers those controlled sequences; it does not reproduce every vendor input or graphics implementation.

On the affected physical device, repeat finalization with a long attributed answer while scrolling, holding a text selection, tapping attributed text, opening/closing source popups, switching profile tabs and navigating away. Test both the original answer length and a document large enough to use multiple stored blocks. The acceptance result is no detached-coordinate exception, no action from a disposed owner, no stale source popup, and correct identity/colours after returning.

### Crash and attribution persistence

Use a disposable test conversation and deterministic saved contributions. Record the body digest, revision identity, source snapshot digests and mapped ranges before each run.

1. Interrupt the process after provisional text is saved but before the final bundle commits. On reopening, preserve the saved body, mark completion as unrecorded and reconstruct only supported links from retained originals. If originals are unavailable, show attribution pending.
2. Interrupt after the final bundle transaction commits but before the normal completed event/animation. Reopening must restore the same body, revision and attribution. The final bundle must not be overwritten by an older queued checkpoint.
3. Interrupt during a long document's manifest preparation. Uncommitted staged payloads must not replace the last committed owner/fence. Reopening must not accept a stale revision or mismatched range digest.
4. Export, reopen and export again. Compare body/source digests, complete source bodies, attribution state and report stage. Do not assign colours by guessing when source data is absent.

Use test hooks or debugger breakpoints at the named transaction boundaries to make timing deterministic. Killing at an arbitrary time without establishing the boundary is not evidence that the text/metadata window was tested.

### Release replay for jank, fading and blur

Use a release or otherwise non-debuggable build with performance tracing available. Keep device, refresh rate, answer bytes, source corpus, scroll path, thermal state and background workload the same across variants. Replay saved output so provider/network variation does not dominate the comparison.

Run four variants: fade on/blur on, fade off/blur on, fade on/blur off, and fade off/blur off. Use the existing response-animation and glass/blur controls or a controlled test configuration; record the actual settings and logged effect states. Include initial streaming, finalization, attribution popup interaction, tab switching and reopening the stored document.

For each variant retain `FRAME_TIMING` records, active refresh/frame budget, frames over 100 ms, worst frame, interval p95/p99, and operation traces for parsing/annotation, source mapping, layout/measurement, document publication and graphics effects. A lower overall average alone is insufficient: inspect the concentrated stall intervals corresponding to the exported 120-of-120 janky interval. Compare shader warnings with actual effect state without assuming a local-model GPU failure.

Record the measurements before claiming a material performance improvement or deciding on a targeted graphics fallback. No physical-device release replay result is asserted in this document.

## Remaining limits and non-findings

- Conservative lexical mapping can still leave valid paraphrases unresolved, particularly multilingual answers and complicated merged propositions. It cannot independently prove that every requested fact is present or factually correct. Keep the source-accounting uncertainty visible and evaluate representative model outputs.
- The coherent answer requirement is implemented through complete readable inputs, topic planning, consistent instructions and local accounting. If a model still omits a relevant unique claim, report that as a remaining editorial failure; do not conceal it with an automatic appendix or a false semantic-verification flag.
- Client-side classification cannot repair the hosted Hugging Face implementation, provider cache contents, quota policy or changing backend aliases. Live provider and device tests are separate from mocked regression coverage.
- Exact source reconstruction depends on retained original bodies and ownership/integrity metadata. When that evidence is absent, pending attribution is the honest result.
- The exported root HEAD 404s/redirects, nonfatal OEM diagnostics, successful tool calls, empty research-worker runs and consent-based tool omissions are not reclassified as confirmed generation failures. The audit did not establish an ANR or a GGUF/QNN/LiteRT/native out-of-memory failure.

These boundaries should remain visible in release notes and the PR description. Green automated checks establish the tested code and contracts; they do not establish unmeasured device performance or repaired upstream services.
