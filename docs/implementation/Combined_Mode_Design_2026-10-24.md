# Combined Mode design implementation — 24 October 2026

This checklist maps the attached **Combined Mode Reliability and Presentation Design (23 October 2026)** to production changes and regression fixtures. It describes implementation coverage, not a claim that a model's answer is factually correct or that the target phone's performance gate has been measured. The existing single automatic synthesis, complete contribution bodies, immutable revisions, stable profile colors and worker-based Markdown preparation remain the foundation.

Paths below are relative to `app/src/main/kotlin/dev/chungjungsoo/gptmobile/`; test class names refer to `app/src/test/kotlin/dev/chungjungsoo/gptmobile/`.

## Delivery and capability

| Requirement | Production behavior | Main code and regression coverage |
|---|---|---|
| D1 — preserve readable output after protocol failure | Only validated committed records reach delivery. Incomplete fragments and malformed tails remain in the record checkpoint; they do not fabricate an end record or erase committed prose. Clean EOF without the required end record is an output protocol failure. Single-pass operation has no automatic model repair. | Existing `CombinedRecordProtocol`, `CombinedRecordStore` and `CombinedRecordRecoverySession`, with corrected failure classification; `CombinedRecordProtocolTest`, `CombinedRecordRecoverySessionTest`, `CombinedDeliveryRepairTest`, `CombinedScopedClaimsTest`. |
| D2 — greeting writer eligibility | Greetings use the same route/protocol/output checks as substantial requests. A 256-token Horde route cannot bypass the minimum framed output allowance. Explicit catalog evidence that a route has no reasoning can remove the speculative reasoning reserve; contrary observed reasoning takes precedence. | `CombinedWriterPolicy`, `CombinedProviderEligibility`, `FreeCatalogState`; `CombinedGreetingEligibilityTest`, `CombinedDesignContractTest`. |
| D3 — one accepted request plan | The complete final prompt, selected history, normalized editorial system, route identity, protocol, required output, effective output and known/unknown context state form one immutable request plan. Snapshot binding verifies prompt/system/history; prepared-envelope validation checks actual turns and route before opening the adapter. Physical dispatch requires that validation and the exact serialized output allowance. A serializer may reject the plan but cannot silently lower its final allowance. | `CombinedWriterRequestPlan`, `AcceptedTaskRef`, `CombinedSynthesisPlanner`, `ChatRepositoryImpl`, `PhysicalAttemptBoundary`; `CombinedWriterRequestPlanTest`, `CombinedFullInputPlanTest`. |
| D4 — useful-output learning | Visible passages alone do not teach sufficient output. Learning requires the final digest-bound report, completed protocol, accepted completion, met length and local topic checks. Reported reasoning and output-limit observations remain separate. | D5 — transport versus prose completeness | A successful transport can retain a partial contribution. | D6 — independent quality dimensions | Reports separately expose displayable draft, protocol completion, scope, identity-link and semantic-support status. | D7 — eligibility before acceptance | The ViewModel checks selected contributor and primary eligibility before accepting a new Combined request and keeps the unsent prompt on failure. ## Cross-cutting behavior

- **Freeze versus decision:** `CombinedCollectionDecisionStore` persists current-attempt acknowledgments and explicit accepted writer selection. The planner waits for unacknowledged failures, then records acknowledged attempts in the frozen snapshot. Temporary chats retain decisions only in memory; chat deletion removes decision roots.
- **Removing a profile:** the existing conversation membership update is reused, with a visible Undo action. Global profile records and historical attribution remain intact. At least one selected profile is retained. A preflight writer change is recorded as a turn decision before collection resumes; changing the settings page alone is insufficient.
- **Research recovery:** the UI captures the full accepted feature/chat policy before queuing. Resource-wait and terminal cards observe the persistent research execution state. Stop persists cancellation, and explicit Continue/Retry/primary selection resumes terminal research execution with a fresh action ID before requesting final delivery. An interrupted attempt is not declared reconciled just to enable retry.
- **Prompt preservation on final retry:** the same-writer retry changes only `target_revision_id` and existing requested/effective policy-digest fields in the JSON envelope. It preserves research question obligations and unknown future fields. Sources, evidence, original task, history, attribution, acknowledgments and other snapshot fields cannot be replaced by resealing a changed snapshot.
- **Attachment-backed final requests:** authorized document expansion and selected model-facing history are captured before freezing in `CombinedWriterContext`. Current document text becomes explicit untrusted source data inside the frozen JSON prompt. Native attachments remain in the captured envelope. Final generation and explicit retry reuse that exact projection without rerunning mutable document extraction. Changed attachment exclusions block stale dispatch.
- **Legacy records:** new source/quality/link fields have defaults, and version-one claim extraction and legacy protocol readers remain available. Historical answers are not rewritten. New digest-bound links are only interpreted under their explicit version; stale spans are rejected.

## Validation boundaries

Build and unit-test outcomes are recorded in the [completed branch-wide validation report](Stability_Implementation_2026-10-24.md). This file records test intent and code mapping and does not substitute for those successful test invocations.

The following acceptance activities require a device or explicit external execution and are not claimed as completed by this implementation checklist:

1. ROG Phone 9 Pro streaming plus grouped-dialog interaction, worst-frame review, and the proposed no-stall-over-100-ms target.
2. Light/dark rendering with 200% font scale, TalkBack focus containment, row/cell reading order, actual touch targets, and backdrop fallback while the app backgrounds or the system reduces visual effects.
3. Live provider tests of framing, reasoning behavior, alias changes and final output caps. Unit fixtures exercise the client contracts without spending provider requests.
4. Human review of nicotine/hydrogen/carrot expected claims and qualifications. Local ID/span/quantity/qualifier checks constrain errors; they do not establish medical truth or complete semantic equivalence.

The request guard rejects model-facing system/history/attachment-envelope drift before any physical request. Authorized document text is captured by the planning path and reused unchanged. Provider serialization still owns wire normalization, native attachment admission and the exact byte-level capacity check; this guard does not compare provider-specific wire JSON with the logical frozen envelope.
