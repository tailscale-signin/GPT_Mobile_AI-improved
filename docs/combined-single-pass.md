# Combined single-pass execution

New Combined turns freeze `singlePass=true` in their accepted policy. Existing saved policies default to false so their serialized digests and recovery contracts remain readable.

## Collection and failure decisions

Every selected, unpaused profile receives the accepted request. Unsupported routes fail capability admission before a provider request. Failed, empty and detectably incomplete contributions block final assembly. A single dialog lists the affected profiles, including model, actionable error, technical details and individual retry/removal controls. Dismissing the dialog leaves the primary waiting and a visible control reopens it.

Retry creates a new attempt for the selected contributor while preserving successful replies and historical revisions. A failed Horde result retrieval checks its durable receipt first. A pending or uncertain job cannot cause a duplicate submission. An explicitly retried, already delivered partial answer may create a new request.

Chat membership is persisted separately from historical response slots and provenance. Removed profiles disappear from the dock and swipe navigation; their late results cannot become inputs to a new synthesis. Historical source records remain available for attribution.

## One primary request

The frozen input includes every remaining admitted contribution's complete answer text, stable profile UID, attempt ID, transport/completeness/evidence states, SHA-256 digest and estimated token count. The claim inventory is an index, not a replacement for response bodies. Readable evidence is distinguished from located URLs and snippets.

Full-input admission reserves output and safety capacity. A capacity failure does not trim contribution bodies, start a multipass inspection, or switch writers. The selected primary is bound into the snapshot and writer identity.

A dispatch identity is persisted transactionally with the frozen corpus. Duplicate taps return the existing run. The durable turn budget independently admits at most one physical primary generation and rejects verifier, continuation and repair roles. Provider transport retries, output continuation, structured-output recovery, delivery rewrites and automatic successor writers are disabled for new single-pass turns.

A user-requested primary retry creates a fresh execution identity using the saved inputs, including after cancellation. It never reuses a cancelled root or restarts the contributor collection. Restoring saved output does not dispatch generation.

## Local checks and rendering

The same request asks for task-appropriate Markdown, material qualifications, deduplication and source references. Local checks assess fixed-count numbered lists, request subjects, evidence availability and pricing units. LLM7/OpenRouter price requests identify API services and require readable official evidence; missing catalogue/model matches must be disclosed without silently substituting a model. These conservative checks do not certify factual accuracy or prove that the model used every sentence.

Validation failures retain usable output and mark the result partial/failed; they do not launch another model call. Diagnostics distinguish profiles included in input from profiles represented in validated final passages, and token estimates from measured usage.

Profile UID colour identities survive removal and reorder. Validated passage offsets are mapped through Markdown transformations during streaming. Shared, unknown and conflicting source declarations stay neutral. A profile colour identifies contribution origin, not fact checking.

Foreground service admission is checked before dispatch. Work that must wait for a foreground activity stays queued, cancellable and persisted. Service-start failures are classified as app execution problems. Identical record checkpoints and unchanged visible-output diagnostic commits are suppressed; reasoning progress remains separate.

## Verification

Regression coverage includes concurrent/restored primary admission, uncertainty versus known non-dispatch, isolated retries, failed-count delivery without verifier/repair, follow-up service resolution, unsupported pricing, complete six-profile payloads with hashes, grouped failures, persistent membership filtering, Room transaction dispatch deduplication, context overflow, stable colours and Markdown/Unicode passage offsets.

Run `:app:testDebugUnitTest` and ktlint 1.3.1. Before release, also exercise these on a phone:

1. Two contributor failures, one retry, one removal, and a late removed-profile callback.
2. Background/foreground transitions between collection and synthesis, including process recreation.
3. Primary truncation and cancellation with preserved partial output and an explicit retry.
4. Streaming colours across headings, bold text, links, lists, tables and emoji.
5. Real route reasoning/output limits, queued-job recovery, search cooldowns and matched official pricing evidence.

Live provider behavior, on-device frame timing and semantic answer quality require those runtime checks; unit tests cannot establish them.
