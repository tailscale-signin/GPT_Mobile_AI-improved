## Recovery boundaries

A provider terminal frame does not complete a repository task. `GitHubVerifiedSession`, request-completion checks and the acceptance ledger continue to establish evidence-based completion. The lifecycle record records that outcome and requires successful delivery before persisting `COMPLETED`.

The output checkpoint is separate from immutable operation evidence. It binds the draft to task authority and the replayed evidence, saves text periodically, claims continuation allowance before dispatch, and stops on malformed tool frames or server-owned action uncertainty. Tools requested by a continuation still pass through normal runner admission, authorization, checkpointing and receipt collection. They are never executed by the output wrapper. A tool handoff needs matching confirmed call receipts before its retained draft can resume; an unknown result remains blocked for reconciliation.

The continuation request budgets the currently selected tool schemas and result reserve. It cannot silently discard schemas during planning and then add them back at dispatch. Full evidence remains in the existing protected journal while the bounded replay tail/context carries only the current model input. A capacity refusal retains the draft and operation receipts.

The runner delivers the authorized outer tool's full receipt to its evidence observers before bounding display or replay content. The raw-receipt callback matches call ID, resolved tool name and arguments, then forwards the runner-owned call carrying its trusted original invocation fingerprint. This permits wrapper-created call objects to report the full result without treating absent internal metadata as a different invocation, while excluding a delegated child's private intermediate receipts. Alias and corrective-recipe routing can change the executed call's spelling without losing the original handoff identity. `AgentRunnerTest` covers full-receipt delivery and delegated-receipt isolation; `GitHubContinuationInvocationTest` and `ToolBatchCheckpointTest` cover identity across routing, compaction and restoration.

Review cache identity includes reviewer revision as well as task and prompt. A changed reviewer can resume saved work, but a cached rejection from the old reviewer cannot masquerade as a fresh result. Missing or invalid prerequisites are reported before dispatch where that fact is known. If usable input capacity is the only missing prerequisite, the checkpoint records `GITHUB_REVIEW_CAPACITY`: zero or unchanged capacity remains blocked, while a larger current allowance resumes the saved candidate without regenerating it or repeating repository operations. The effective allowance remains bounded by the configured review input limit. Unknown dispatch status is left absent rather than inferred from unrelated earlier tool calls.

MCP recovery retries only explicitly read-only methods. A lost tool-call response remains an unknown outcome. Successful initialization and cached schemas are insufficient for execution; current discovery and recent connection proof are required. Cancellation remains cancellation instead of being relabeled as an unreachable endpoint.
