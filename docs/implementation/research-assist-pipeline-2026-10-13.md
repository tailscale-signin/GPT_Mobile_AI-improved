# Research and Local Assist pipeline repair

Base: `feat/unified-reliability-v2-2026-10-13` at `bc191c6abf8d6bc732a31fab0cf1b0c333a34cb0`.
Incident: diagnostics from Android 0.9.52.0 build 121 (`04babee8`). The private log is not committed.

## Execution changes

Direct Research now supplies a typed model coordinator rather than a null generator. Planning, gap analysis, exact-quote extraction, and claim review have separate schema contracts and receipts. It attempts an explicitly permitted local helper before the selected primary. A nominated reviewer is considered only with its existing permissions. No newly discovered account, model, tool, or remote destination is silently authorized. Generation cannot call tools or recursively delegate. Revoked/changed profiles stop dispatch; parent cancellation is propagated, not retried.

A model gets two failed physical stage attempts before its run-scoped circuit opens. Unavailable local inference does not cancel native discovery or discard source evidence. Review can be self-review; independence is claimed only when both model identities are known and distinct. This is passage support, not proof of scientific validity or publication peer review. Source counts, reviewed claims, independently reviewed claims, and final answer delivery remain separate.

Complete task and evidence reach typed stage admission without legacy character slicing. Native/source article readers still expose their actual retrieval quality and retained excerpt/full-body availability. Sources and quotes are not rewritten by a selection helper. Complete local claim packets are added within remaining writer context. Packets that do not fit remain in Research history, with an explicit notice. Only an exact complete packet observed in the final serialized request can count as included; a producer marker alone cannot.

## Assistance readiness and scheduling

New policy defaults permit automatic preparation, 20-second tasks and eight attempts. Existing explicit stored settings, optimization-mode restrictions and processing permission decisions remain authoritative. Research preparation, queue waiting, preparation context and automatic/warm-only preparation are visible controls. Fixed-context exports keep their declared allocation.

Cold preparation pins the runtime identity after loading, not before it. A healthy first request is admitted without an unconditional 30-second delay. Genuine thermal/memory pressure still requires stable recovery. Failed preparations have a configuration-scoped cooldown; changing the configuration permits a fresh check. One cancellation-safe local queue serializes optional helper work without replacing the native runtime ownership lock. The per-turn physical attempt allowance is shared across research and ordinary assistance. Original evidence survives queue timeout, invalid output and missing runtime.

Function-calling support is not invented for chat-only exports. Evidence preparation deliberately uses tool-free inference; the parent executes authorized tools. Existing artifact capability inspection and rejection remain in force.

## Research acquisition and tool repair

Academic aggregate search/read deadlines now encompass their physical HTTP retry allowance. Individual HTTP attempts retain connect/socket/request limits; user Stop and parent cancellation remain effective. Completed provider receipts and evidence survive slow or failed peers. The academic observer uses nonblocking queue admission and drains persisted overflow after discovery, so a full reader queue cannot hold a completed provider inside its network deadline. Failed pages retain resumable cursors.

Only explicitly known read-only academic operations can be retried after read failure/deadline. Unknown-outcome mutations still require reconciliation. Existing user research limits and physical HTTP accounting are not removed or bypassed.

Required provider query aliases take priority over optional alternatives; news searches receive `q` when required. Unknown required fields are rejected, not fabricated. Progressive tool discovery now bounds schema tokens as well as the initial tool count and replaces older advertised tools instead of accumulating the entire catalog. Oversized individual definitions are reported as excluded, never silently treated as available.

## Runtime, memory and diagnostics

The selected llama server's known model-load failure is cached briefly by profile/route/model/credential identity. An explicit recheck or changed route/model can retry; an expired transient failure cannot block forever. This does not claim to repair a missing server model file or remote GPU allocation.

Local memory admission reports required, reserved and available bytes, context size, estimate method, and whether native load was attempted. Conservative unmeasured memory estimates are not relabeled as measured engine allocation or bypassed. Smaller helper-context selection is explicit. Calibrated device peak-memory profiles still require physical device benchmarks.

UI-hidden callbacks no longer force immediate embedding teardown. Actual running/background pressure still releases idle resources and starts a reacquisition cooldown; exact/topic recall remains available. Enrichment cannot close an interactive local conversation. Structured output must contain allowed fact kinds and exact source quotes; one bounded schema repair is permitted within the original deadline. Exhausted work retains its source for explicit/later retry rather than losing pending work.

Research history includes model/stage outcome, duration, estimated tokens and independent-review status. Debug Local Assist shows actual invocation token values, provenance, backend, duration, failure/skip state and exact serialized-request inclusion. Model-based estimates remain labeled estimates.
