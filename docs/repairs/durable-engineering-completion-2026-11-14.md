This component extends the retained job engine. It preserves known context
capacity and the actual provider output allowance; bounds replay to the remaining
context; offers smaller read-only PR/context contracts while retaining discovery;
and permits bounded revision-aware source searches and line reads between coding
steps. Source-edit authority comes from exact original ranges actually delivered after
request compaction. Large READ and IMPLEMENT contents use authenticated artifacts
before bounded journal serialization. A READ retains its current pinned head
separately from an unchanged artifact's original creation provenance.

Follow-ups retain a verified conversation/branch/actor PR owner, using that same
marker when creating the first PR. A predecessor without an observed actor does
not invent inherited ownership. Source preparation synchronizes the approved
mirror to an exact GitHub commit/tree before isolated validation. Commands observe
cancellation and the remaining task deadline before launching and while running.
Independent branches can advance through a bounded pool; one branch remains
serialized. This is not a specialist-agent implementation.

Terminal required skipped/neutral checks and startup/action-required failures have
a blocked outcome instead of endless polling. Merging and qualifying the merged
revision are distinct. Qualification discovers literal push triggers from workflow
blobs at the merge commit, evaluates supported branch/path filters against that
commit's first-parent diff, and requires successful matching main-branch push runs
for every applicable workflow. Foreign branch/event/repository runs cannot replace
that evidence. Unsupported YAML/globs, incomplete path coverage (300-file API
boundary), and an unavailable workflow contract remain blocked. A stable inventory
observation is additionally required. Artifact installation and physical smoke
checks are not inferred from workflow success. The saved immutable completion
receipt is written only after the final post-merge verdict is incorporated.

Windows settings gain a behavior-check form mapping an exact objective, source,
JUnit case/report, approved command and CI check. Saving a mapping does not execute
or qualify it. The dialog lives in Advanced settings, validates the complete
policy, and rejects duplicate mappings without changing the form. Existing
dirty-state, revision, repository and lifecycle guards disable it while stale.

Focused host evidence: production source/continuation/post-merge/cancellation and
settings regressions; an actual temporary Git mirror; large-file tail inspection;
and two current Kotlin facade/catalog regression methods (ordinary repository
schema: 2,680 UTF-8 bytes, 894 estimated tokens). Synthetic-provider/host fixtures
are not Android, installed Windows, Docker, live-model, or end-to-end qualification.
The new repeated-compaction Runner regression and all combined-source CI must pass
before merge. Benchmark mutation evidence must retain the companion correction's
explicit trust boundary; a candidate-process Boolean is not independent proof.
Correct observed outputs remain visible while full contract resolution and overall
scores stay unavailable; this evaluator gap does not trigger needless model
repairs. Actual incorrect outputs still use the configured repair budget.

The full issue-disposition union, final generated inventories, source composition,
CI receipts and merge/closure are tracked on PR #1203. This note does not certify
those still-pending operations or all architectural acceptance scenarios.

The implementation does not add specialist explorer/test-investigator agents or
automatically discover task-specific acceptance mappings from arbitrary prompts.
Live production-model qualification across every interruption scenario remains
separate from the bounded synthetic-provider regressions.
