# Pinned LiteRT structured-output repair notes

## Evidence and limits

The user supplied repeated NPU grammar rejection of `▁reasoning` and GPU output beginning with a duplicated JSON opening sequence. Those are audit observations, not a locally replayed device result. The original export and phone are unavailable in this workspace.

The app pins LiteRT-LM **0.18.0**. Review of that exact Kotlin callback implementation confirms that `MessageCallback.onMessage` delivers a chunk. `LocalRuntimeImpl` already concatenated those chunks; no application-owned opening brace was found in the adapter path. Removing an apparent duplicate from returned text would conceal the native failure and is not an accepted repair.

Two upstream reports provide specific compatibility hypotheses, without establishing the cause on the user's device:

- [LiteRT-LM #3463](https://github.com/google-ai-edge/LiteRT-LM/issues/3463) reports interaction between thinking configuration and response-format constrained decoding.
- [LiteRT-LM #3944](https://github.com/google-ai-edge/LiteRT-LM/issues/3944) reports malformed structured output with Gemma speculative decoding, including an Android 0.18.0 report.

The exact pinned [Conversation.kt](https://github.com/google-ai-edge/LiteRT-LM/blob/v0.18.0/kotlin/java/com/google/ai/edge/litertlm/Conversation.kt) and [native conversation implementation](https://github.com/google-ai-edge/LiteRT-LM/blob/v0.18.0/runtime/conversation/conversation.cc) were reviewed. No runtime upgrade or unverified device-fix claim follows from those reports.

## Implemented boundaries

`LiteRtLmAdapter` disables speculative decoding before a structured request initializes its engine. Planner/router tuning preserves that explicit false value. The runtime also applies thinking=false and speculative=false to the conversation and an explicit thinking=false to the structured message call. Reusing an engine initialized with speculative decoding for a structured request is rejected. These are app-applied safety settings; the SDK's absent native-effective acknowledgement remains absent.

`LocalStructuredOutputCapture` receives the original visible deltas without adding, removing or repairing prefixes. At a successful SDK terminal callback it checks strict JSON and the supported object-schema constraints with a bounded buffer. Malformed syntax, schema mismatch and validation-buffer exhaustion have separate error codes. The raw stream and native timing/counters remain available even when format validation fails.

`CONSTRAINED_DECODING_FAILURE` is assigned only when the error contains grammar/token-mask evidence. It survives QNN wrapping and Binder transport instead of becoming an unknown native error or a tool-call limit. Native error text is bounded and redacted, while in-process causes remain attached. Cancellation and unrelated parser failures keep their original classification.

## Readiness and alternative decoding

New large benchmark runs perform separate repeated probes for every exact schema in their frozen plan. Probe records, including an interrupted probe, are durable and excluded from the counted capability samples. A native failure can be followed by a prompt-only compatibility experiment only after safe cleanup. A successful alternative requires three strict passes with the same observed loaded-configuration key.

The key binds artifact content, runtime/library identity, device/firmware, the loaded engine's backend/context configuration, sampler request, schema and execution policy. This configuration identity does not establish physical accelerator execution. Normal prompt-mode requests recompute it after loading and before generation. A changed key fails without a generation. GGUF does not claim a native JSON grammar; its prompt-only mode must be proven separately. Automatic mid-generation backend changes cannot reuse a key belonging to another backend.

The schema is included before context admission in prompt mode. Benchmarks do not silently repair malformed JSON, replay tools or replace a failed primary score with a recovered answer. The original failure, selected mode and recovery/probe lineage remain visible; recovered configurations remain separate, provisional populations.

## Receipt meaning

Engine and generation receipts distinguish app-owned SDK object/request IDs from unavailable SDK-native identities. Requested values, submitted SDK settings and native-acknowledged values are separate fields. NPU's runtime-default sampler is not reported as a confirmed temperature. Driver identity and actual accelerator proof remain unknown when the runtime cannot expose them.

The isolated worker's load policy, process supervision policy and GGUF native prefill/decode/absolute policy are separate from the benchmark's total deadline and observed phase durations. A terminal callback can establish completion without proving the finish reason, answer correctness or accelerator qualification. Cleanup and positive worker-exit evidence remain independent obligations.

## Validation

Production strict-output/QNN tests passed 13 focused cases, including split JSON deltas, duplicated prefixes, malformed syntax, schema mismatch, bounded capture, preserved native token detail and worker error-category round trip. Integrated SDK/mock, adapter, benchmark readiness and device regression results belong in the [release validation record](release-0.9.60.0.md). Repeated crash-free schema tests and a measured reduction in warm inspection on the actual device remain unfulfilled until device evidence is captured.
