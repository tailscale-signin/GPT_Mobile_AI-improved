## Acceptance and task state

`GitHubAcceptanceContract` compiles an engineering request into stable source-linked criteria, dependencies and evidence producers. Quoted material and conditional constraints cannot grant new authority. Refining a retained contract preserves the original request digest, scope, tool allowance, time allowance and deadline.

`GitHubCriterionAcceptance` requires evidence specific to each deliverable:

- Inspection needs actual nonempty pinned source windows with matching blob identities. Instruction coverage is joined only across the same repository, task binding, path, blob, revision and total line count; every explicitly named instruction file must be complete. Search inventories and summary-only coverage cannot substitute for content.
- A correctness finding cites observed non-instruction source. Its factual claims still pass the existing claim verifier.
- A requested new feature branch needs a verified live branch-creation receipt for the implementation's repository and branch.
- A new regression must be added or modified in the committed change set, with source or retained patch content at that revision and successful complete test-job evidence. An unchanged test read cannot satisfy it.
- Diff review needs complete pinned comparison coverage. Draft delivery needs the actual draft-creation operation and its matching live PR/head readback. Ordinary PR receipts cannot lend their proof to a draft operation, and unrecognized title, repository or other constraints remain unverified.
- Dependencies remain separate obligations. A patch, a response, or a report cannot complete an unfinished task by itself.

`GitHubEffectiveRecovery` joins only same-task protected output checkpoints to the task verdict. A current typed recovery refusal takes precedence over an older provider cooldown or completed child response. Task state, response delivery, child-attempt state and pending criteria remain independent. Persisted phases do not invent a running executor or a scheduler wake that was never observed.
