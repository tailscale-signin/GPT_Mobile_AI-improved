# 0.9.60.0 — Research, free-provider privacy and Combined integration

Draft release; version code 128. Based on `fix/research-free-provider-hf-2026-10-24` at `de1e67b`.

## Changes

- Add reviewed, typed retention policies and device-local activation receipts for known free routes, including profiles imported as compatible/custom clients. Collecting or unverified routes require acknowledgement before activation and at dispatch. A verified no-retention classification permits default activation regardless of account authentication; no current route is promoted to that classification without sufficient evidence.
- Separate activation from personal-tool consent. Grants name a profile, model, credential identity and policy; cloning or changing those inputs cannot inherit a grant. Prohibited or unbounded downstream routes cannot unlock personal tools. Preserve public web/date/calculator/academic tools, subject to the existing chat and plugin switches. Revalidate personal-tool permission before execution and before releasing results.
- Exclude device-local consent from backups and invalidate it on settings restore. Disable unacknowledged/retired profiles during startup reconciliation while preserving saved conversations, profile identities and explicit OFF choices.
- Remove PorchLM and OpenCode from executable catalogs and selectors; reject their exact retired endpoint aliases even through a manually imported compatible profile.
- Persist local rolling quota windows and provider cooldowns together. Respect Retry-After seconds and HTTP dates, compensate for server clock skew, and retain in-process monotonic deadlines. Show a shared countdown and recheck availability when starting a chat.
- Add Room-backed provider waits for work blocked **before its first dispatch**. One WorkManager queue per quota scope revalidates current membership, configuration, consent, inputs, deadline and ownership fence. Cancellation terminalizes waiting owners. Restart reconciliation retains the wait; no foreground service is kept alive for a cooldown. Transmitted requests are never silently replayed.
- Give each Combined user turn a dedicated canonical final-message identity. Preserve the contributor rows and their revisions. Reuse the final slot on retries/regeneration and keep late final messages grouped with the originating user turn.
- Stage strict single-pass finals until the final answer is ready. Account for all retained source blocks with source/final UTF-16 spans and content digests; keep code, tables, Unicode, qualifiers and conflicting claims. Unmapped material remains attributed source excerpts, explicitly unverified. Identical complete sources can share ownership; matching sentences in different contexts cannot silently collapse.
- Fall back to deterministic on-device source assembly when the complete input exceeds the frozen writer context, or private source transfer is not authorized. Preserve explicit user length/format constraints by requiring review when source assembly cannot satisfy them. Local assembly uses the same final identity and fenced atomic publication and performs zero writer requests.
- Retain exact source links in unlinked gaps and shared-source ownership, separate source accounting from factual verification, and avoid treating an unevaluated lexical audit as successful coverage.
- Reuse bounded per-source extraction caches and defer marketplace directory initialization to its existing IO path.
- Include the base branch's Hugging Face terminal diagnostics, shared Research stage-completion handling, typed repair failures, bounded extraction/review packets, preserved best usable attempt and per-profile statistics.

## Compatibility and storage

Room schema 46 adds `combined_final_messages` and `provider_waits`; migration 45→46 is additive and backfills historical final identities. Consent receipts are device-local authority, not portable preferences. Legacy snapshots keep their original framing because source preservation is explicitly marked in newly frozen prompts. The existing one-physical-writer-request contract remains the default; this release does not retroactively change saved policies.

## Remaining design/release gates

The three supplied designs describe a broader program than one safe automatic retry policy. The following remain explicit review gates rather than claims of completion:

- General automatic continuation after a **transmitted** rate-limited Research stage requires a separate persisted stage-specific resume contract. This release automatically resumes only never-dispatched requests; existing evidence and explicit recovery remain available after transmitted failures.
- Optional append-continuation final mode requires a separately versioned accepted policy, writer-record cursor and UI. It is not enabled by weakening strict single-pass dispatch.
- Complete category/recipient/time-limited personal-data transfer authorization and derived-query taint tracking are not implemented. Ambiguous downstream routes remain blocked; private tool contributions are conservatively retained on device for final assembly.
- Daily token reservation/reconciliation across provider-specific quota headers and account/credential-keyed model-health summaries need provider-specific contracts; current persistence covers rolling request windows and observed cooldown evidence.
- Durable block manifests and virtualized rendering within very large final answers remain follow-up work. This draft stages the answer in memory and commits the body and source-accounting report through the existing fenced message publication.
- Physical-device rendering/scroll memory benchmarks, screen-reader interaction, offline/reboot WorkManager liveness, full permission-flow screenshots and live endpoint probes remain manual qualification. No Hugging Face replacement endpoint or upstream restoration is claimed.
