## Runtime documentation review

The app remains on LiteRT-LM 0.16.1 and the verified QAIRT library set. The Kotlin SDK's `Backend.CPU(threadCount=…)` supports the new CPU setting; zero in the UI keeps the SDK default. `EngineConfig.cacheDir` accepts a writable cache directory or `:nocache`. Both settings participate in warm-engine validity so a new choice cannot silently reuse old settings.

CPU, GPU and NPU are alternative language-model backends. A supported multimodal package may use a separate GPU vision encoder. Enabling all processors together is not an exposed Kotlin API. Maximum thread counts do not establish maximum throughput; thermal and memory controls remain active. The NPU requires matching compiled weights, SoC dispatch and vendor libraries. Installed prerequisites are not a successful native inference test.

The previous audit's model integrity, request ownership, context budgets, QNN fallback policy and native APK hash/alignment checks remain in place. GPU/NPU model choice is made in the profile and the router reports the backend that actually loaded. Keep-warm affects scheduled idle unloading; Android memory-pressure cleanup remains active.

## Map service boundaries

Nearby search sends coordinates to Overpass only when a category is requested. Selecting a place sends endpoints to FOSSGIS routing. Tiles load through OpenFreeMap. The UI retains attribution and an OpenStreetMap correction link. Requests are serialized, rate limited to less than one per second, capped at 1 MiB and cached for five minutes with at most 32 entries. Radius is bounded to 100–5000 metres; at most 500 OSM candidates and 12 displayed places. Results are the nearest returned matches, not a completeness or opening-hours guarantee. No background scraping or autocomplete requests are issued. These shared public services need a dedicated deployment/provider if app-wide demand outgrows their published limits.

Driving/walking times are routing-engine estimates without live traffic. Map rendering, location permission, GPS, service availability and marker gestures need physical-device acceptance. Generic .litertlm imports retain conservative capabilities; this release does not convert GGUF models or add another native engine.
