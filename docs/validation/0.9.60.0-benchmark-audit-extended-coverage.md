## Additional report: benchmark export crashes

The user subsequently reported that exporting benchmark results crashes the app. No device crash trace was supplied, so the precise on-phone failure is not established. The previous path retained the serialized backup, parsed and normalized history trees, a redacted output tree and the final JSON string together. An isolated Java 21 replay of that old helper with a **100,755,765-byte synthetic history** failed with `OutOfMemoryError: Java heap space` under `-Xmx256m`, in `JsonToStringWriter` growth. The captured input hash and original failure are retained with the validation evidence. This reproduces the allocation defect on synthetic data; it does not establish the cause of the reported phone crash.

The app calls `BenchmarkStore.writeExport` on IO under the store snapshot lock. It no longer calls `loadLocked` before export. `BenchmarkColdExport` reads canonical records through bounded SQLite chunks and retains lightweight comparison data; complete individual runs are loaded when grading requires them. `BenchmarkStreamingExport` redacts records and emits derived sections incrementally, then flushes without closing the caller's stream. SQLite offsets use Unicode code-point counts, preserving supplementary characters at chunk boundaries. The initialized database remains authoritative even when empty, so a stale optional preference mirror cannot repopulate cleared history. Working memory may still include one complete record plus derived metadata; the change does not promise unlimited single-record size.

All stored runs, attempts, active scores and runtime evidence remain in the export; diagnostic mode also retains score history and batch events. Unknown fields, historical grades, captured enrollment/policy populations, truthful in-progress state and redaction remain covered by the relevant production-path checks. The recovered original four-run benchmark passed a compatibility round-trip preserving all original raw-record fields in the checked sections, including its 110 samples and 110 attempts. This earlier source is separate from the unavailable 250-result audit population.

`ProfileBenchmarkViewModel`, `BenchmarkExportArtifactStore` and `BenchmarkExportDestination` prepare a complete private file and small integrity receipt before bounded copying to the selected Android document destination. The picker receives a filename, not the JSON payload. Picker/open/write/close failures and cancellation retain the verified file for exact-ID retry; a diagnostic retry rechecks current Debug Mode. Success is reported only after destination close. Stale-orphan cleanup respects active OS file leases and does not remove published complete exports.

**Earlier focused production-path evidence passed:** `BenchmarkStreamingExportStoreTest` (two) checks legacy-helper parity, all canonical sections, unknown fields, Unicode chunk boundaries, redaction, in-progress snapshots, output-stream ownership and retry after an I/O failure. `BenchmarkExportArtifactStoreTest` (nine) and `BenchmarkExportDestinationTest` (four) cover bounded copy, restart/retry, cancellation, corruption, close failure, orphan cleanup and picker failure. Existing `BenchmarkExportTest` (four) and `BenchmarkVersionedExportTest` (seven) also passed at that checkpoint.

**The earlier integrated 256 MiB gate passed both `BenchmarkStreamingExportHeapTest` cases.** The large case streams more than 96 MiB of output containing 1,024 complete raw bodies from over 40 MiB of retained history, checking incremental raw-body digests/counts, redaction and the final JSON boundary without constructing the output string. Together with the seven Research/debug-bundle heap cases, that checkpoint passed nine of nine with no skips.

The continuation adds `BenchmarkColdExportTest`, `BenchmarkColdStreamingExportStoreTest` and `BenchmarkColdStreamingExportHeapTest`. Prepared standalone Room checks passed, including a 256 MiB cold export of **101,541,461 bytes with 128 complete raw answer bodies**. The cold case is included in the explicit CI heap gate; final integrated execution remains pending. Real Android document-provider behavior and the user's original crash remain device validation tasks.
