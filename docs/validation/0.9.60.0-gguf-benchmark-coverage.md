## Qualification boundaries

No physical Android device is attached to this workspace. Unit tests, host-native tests, APK assembly and instrumented-test compilation cannot establish GPU execution or rendering performance on the reported ROG Phone 9 Pro. Both requested GPU backends need matching actual device, driver, build, model, offload, prefill/decode, repeated-request and cancel/recovery receipts. Unsupported generic hardware may report an explicit capability skip; a required compatible-device job must fail instead of skipping its required backend.

CPU experiments must retain exact resolved settings, repeated fixture identity, cold/cache-hot regime and available thermal/scheduler observations. Battery percentage changes are context, not energy measurements; an observed thread slowdown does not justify a universal preset. Memory admission equations and trace hooks need physical calibration before reporting performance or memory improvements.

The earlier benchmark export, original diagnostic JSONL and Combined ZIP have now been recovered with the identities linked above. The continuation review reports a compatibility round-trip of the earlier four-run benchmark file; exact original France wording and Portugal report fields supply specific regressions. This is not complete device, diagnostic or conversation replay, and does not substitute for the still-missing later 16-run benchmark export. Regression inputs reconstructed from the reviews remain reconstructed. Preserve original failed samples, export identifiers, grades and policies; a later recovery or revised fixture produces new evidence rather than rewriting the baseline.

Live endpoint availability, authenticated generation, provider-specific rate-limit headers and real remote cleanup remain separate qualification tasks. Source attribution, benchmark answer grades and receipt completeness are distinct from independent factual verification.
